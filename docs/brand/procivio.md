## 1. 이름 구조

| 조각 | 출처 | 의미 |
|------|------|------|
| **Proci-** | process / procedure | 업무 절차·프로세스 |
| **-viv-** | Latin *vivus* / *vivo* | 살아있는, 살아 움직이는 |
| **-o** | 제품 브랜드 어미 | Celonis, Signavio, Camunda형 고유명사화 |

합친 해석:

> **“살아 있는 프로세스”** — 한 번 그리고 끝나는 정적 맵이 아니라, 인터뷰·버전·계층 구조로 **계속 갱신되는 프로세스 지식 자산**.

“살아 있다”를 제품 기능으로 번역하면:

- 버전 라이프사이클 (Draft → … → Published, As-Is / To-Be)
- 체크아웃·권한·승인자 거버넌스
- LLM 추가 질문·분기·구조 제안
- 하위프로세스 참조(Call Activity)로 맵 간 연결

현재 코드베이스(맵 에디터 + 버전/RBAC + AI 채팅 일부)와 방향이 맞는다.

## 2. 제품 정체성

### 2.1 정의

**Procivio**는 현업·전문가와의 **대화(인터뷰/채팅/음성)** 로 업무를 파악하고, 이를 **레벨별·계층별 구조로 DB에 적재**하며, 그 구조에서 **프로세스맵을 자동·반자동으로 렌더링**하는 엔터프라이즈 **프로세스 지식 플랫폼**이다.

핵심 파이프라인:

```text
[Inquire]   대화·인터뷰           →  지식을 수집 (living intake)
     ↓
[Structure] 계층·버전·권한 DB     →  프로세스를 정본으로 유지
     ↓
[Canvas]    맵·분기 시각화        →  구조를 보이게 함
```

### 2.2 시장에서의 자리 (비교 한 줄)

| 상대 유형 | 대표 예 | Procivio 구분 |
|-----------|---------|----------------|
| 다이어그램 | Lucid, Miro, Visio | 그리는 도구 vs **구조가 본체**, 맵은 뷰 |
| 엔터프라이즈 모델링 | Signavio, ARIS, Blueworks | 거버넌스는 유사, 진입은 **AI 인터뷰·구조화** |
| 프로세스 마이닝 | Celonis, KYP 등 | 시스템 로그 vs **사람·업무 지식 구조화** |
| 실행 BPM | Camunda, Appian, ProcessMaker | 실행·오케스트레이션 vs **설계·저장소·맵** |

### 2.3 카테고리 문장 (RFP·제안서)

- EN: *Not process mining. Not whiteboarding. Interview-to-structure process architecture.*
- KO: *마이닝도, 화이트보드도 아니다. 인터뷰로 구조를 만드는 프로세스 아키텍처 플랫폼이다.*

## 3. 제품 라인 (납품 단위)

회사/플랫폼 브랜드 하나 + 모듈 확장. 폴더·도메인은 플랫폼명만 쓴다.

| 모듈 | 역할 | 비전 / 현재 코드 대응 |
|------|------|------------------------|
| **Procivio** | 플랫폼·회사 브랜드 | 전체 |
| **Procivio Inquire** | LLM 인터뷰·채팅·음성 → 구조화 | “말하면 구조화·분기” |
| **Procivio Structure** | 계층 프로세스 DB·버전·RBAC | 맵/버전/권한 백본 |
| **Procivio Canvas** | 노드·엣지·자동 드로잉·편집 | 현 에디터 |
| **Procivio Compare** | As-Is / To-Be 비교 | 현 비교 기능 |

제안서 문장 예:

> *Procivio Structure*에 축적된 L0–Ln 프로세스를 *Procivio Canvas*가 렌더링하고, *Procivio Inquire*가 신규 인터뷰로 구조를 확장한다.

## 7. 강점

- 조어라 Visio·Celonis·Signavio 등과 **직접 명칭 충돌 가능성이 상대적으로 낮음** (단, 정식 상표 조사 전제).
- 3~4음절 `-io` 엔터프라이즈 SaaS 패턴 → 글로벌 데모·영문 RFP에 자연스러움.
- Inquire / Structure / Canvas / Compare **제품 라인 확장**이 이름과 충돌하지 않음.
- “living process”가 버전·인터뷰·갱신·거버넌스 스토리와 연결됨.
- “BPM / Process Map” 직역보다 **단가·카테고리**를 드로잉 툴이 아닌 플랫폼으로 올리기 쉬움.

## 8. 약점과 보완 (핵심)

약점은 “인정”만 하지 않고 **리스크 → 보완 수단 → 검증/완료 기준**으로 관리한다.

### 8.1 이름만으로 제품이 안 떠오른다

| | |
|--|--|
| **리스크** | Procivio만 들으면 “뭐 하는 회사인지” 모름 → 검색·콜드메일·전시 부스에서 이탈. |
| **보완** | ① 모든 대외 1화면에 **고정 부제** 부착: *Interview. Structure. Map.* 또는 *Process knowledge platform*. ② 로고 워드마크 옆에 작은 카테고리 라인. ③ 제안서 표지: 브랜드 + 한 줄 정의 필수 템플릿. ④ 도메인 랜딩 히어로에 3단 파이프라인 다이어그램(Inquire→Structure→Canvas). |
| **검증** | 비개발 임원 5명에게 이름+부제만 보여주고 “무엇을 하는 제품인가?” 한 문장 회수 → 3/5 이상이 프로세스/맵/구조 중 2개 이상 언급하면 통과. |

**고정 공식 (복붙):**

```text
Procivio — Interview. Structure. Map.
대화로 구조를 만들고, 구조에서 프로세스맵을 그립니다.
```

### 8.2 한국어 “프록시비오” ↔ proxy 혼동

| | |
|--|--|
| **리스크** | IT 청중이 reverse proxy / API gateway로 오해. 검색어 “프록시” 오염. |
| **보완** | ① 공식 한글 표기는 **프로시비오**로 고정 (사내 문서·자막·TTS). ② “프록시비오”는 비권장 표기로 명시. ③ 첫 발표·제안서에 발음 가이드 1줄: *프로시비오 (Procivio, pro-SIV-ee-oh). proxy와 무관.* ④ 한글 SEO/보도자료 키워드에 “프로세스 맵”, “프로세스 지식”을 브랜드 옆에 병기. |

**30초 스토리 카드:**

> Procivio는 process와 ‘살아 있다’는 vivo를 붙인 이름입니다.

> 컨설턴트가 하던 디스커버리·구조화·맵핑을 제품으로 만든 것에 가깝습니다.
